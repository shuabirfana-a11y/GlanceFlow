# Final Judge Q&A

## 1. 为什么不是 OCR + Calendar？

OCR 只输出文本，无法保证时间角色、证据可信、日历冲突、确认一致性和写入结果。GlanceFlow 在执行前验证字段证据和时间语义，在执行后回读并恢复，把识别错误与现实副作用隔离开。

## 2. Agent 到底体现在哪里？

Agent 根据当前目标、证据、风险、工作流状态和工具前置条件，在执行、确认、澄清、重采、阻断与恢复之间选择动作。它一次只调用一个白名单工具，并留下公开 Decision Trace。

## 3. 为什么不用 LLM 直接调用 Calendar？

模型输出具有不确定性，直接调用会绕过确定性的安全门、确认快照和事务验证。当前 Demo 不依赖网络 LLM；即使未来加入模型，也只能提出草案，不能取得写入授权。

## 4. 为什么需要 Safety Gate？

Safety Gate 把证据完整性、图像质量、时间矛盾和字段约束变成确定性门禁。未验证草案只能澄清、重采或阻断，不能进入外部行动。

## 5. Action Preflight 是什么？

它是写入前的行动预检，检查重复通知、日历冲突、目标日历和事务计划。它不等于完整反事实推理，也不会自动改时间；发现冲突时要求用户明确接受。

## 6. 为什么要用户确认？

用户确认绑定标题、开始时间、地点、截止时间、日历和证据摘要。HUD 显示或 OCR 中出现“确认”都不算授权；任何关键字段变化都会使确认失效。

## 7. 为什么创建后还要回读？

API 返回成功不代表服务器最终字段正确。系统按稳定 `event_id` 回读标题、时间、地点和私有事务元数据，只有一致才提交为已验证状态。

## 8. 部分创建失败怎么办？

双事件事务中任一创建或回读失败，会补偿删除已创建事件并验证不存在。如果回滚也失败，系统保留残余 `event_id`，明确阻断并要求人工恢复，不把失败隐藏成成功。

## 9. 为什么 Agent 有时选择不执行？

高价值现实行动的错误代价高于一次澄清或重拍。证据不足时延迟行动是保护性选择；评测同时统计目标完成和不必要澄清，避免靠全部阻断获得虚假安全。

## 10. 0/20 错误执行能说明绝对安全吗？

不能。它只表示在当前 20 个本地合成/故障注入场景中未观察到 Agent 错误执行。样本小、分布有限，也没有真实用户、真实校园或实体眼镜验证。

## 11. 为什么只有 20 个 Agent 场景？

这是一组固定、可重复、三系统共享的工程验证集，重点覆盖确认、冲突、重复、超时和回滚边界。它适合比较机制差异，不足以估计真实世界总体性能。

## 12. 有没有真实用户？

没有，当前参与人数为 0。仓库只有招募、同意、任务协议和记录模板，没有生成任何假参与者、均值或 SUS 分数。

## 13. 有没有真实校园数据？

没有许可并独立标注的真实校园采集样本，当前数量为 0。现有核心评测主要是固定种子合成素材；网页素材始终标为 PUBLIC_WEB，不冒充现场采集。

## 14. 有没有 Rokid 真机？

没有。本项目实现并测试了设备边界、Fake/Local Adapter 与 SDK 不可用状态，但当前状态明确是 `NOT_YET_TESTED_ON_ROKID`。

## 15. 没有真机为什么还能证明系统？

模拟器能验证与具体硬件无关的核心：证据、时间语义、风险决策、确认、幂等事务、回读和恢复。它证明接口与安全闭环可运行，但不能替代真机兼容、功耗、网络和延迟验证。

## 16. 给你 Rokid 后怎么接？

实现现有 Camera、Voice 和 HUD Adapter 协议，通过 DeviceBridge 处理连接、去重、时钟和 fallback。设备层只提供输入输出，不得绕过 Evidence、Safety Gate、确认和 Trusted Transaction。

## 17. 哪些代码借鉴了开源？

GlassKit 与若干眼镜项目只用于设备边界设计参考，PaddleOCR 用于可选 OCR 接口研究。当前 Stage 12 声明没有复制或改写上游实现，具体来源和 commit 记录在 `NOTICE-THIRD-PARTY.md`。

## 18. 哪些是 GlanceFlow 自己的核心？

字段级 Evidence Binding、TemporalField 规范时间表示、风险动作策略、确认快照、Safety 与草案绑定、Action Preflight，以及带回读、补偿回滚和精准撤销的事务闭环。

## 19. 为什么 RapidOCR 还是默认？

RapidOCR 在 Windows 本地 CPU 上可离线运行，已接入现有证据链。PaddleOCR 尚未在第一批真实校园数据上完成公平对比，因此不能仅凭预期收益替换生产默认。

## 20. 当前最大的不足是什么？

缺少获得许可的真实校园样本、真人用户和实体 Rokid 验证。因此当前结论是架构和仿真证据，不是现场可用性或大规模统计结论。
