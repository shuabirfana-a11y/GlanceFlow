# 评委问答

## 1. 这和手机拍照识别有什么区别？

核心区别不在相机形态，而在行动安全闭环：字段证据、安全状态、预检、明确确认、回读、回滚和撤销。当前眼镜形态只是本地模拟。

## 2. 为什么必须用眼镜？

眼镜适合用户经过公告栏时低摩擦捕获，但技术闭环不依赖某款设备。我们尚未证明“必须用眼镜”，只验证了第一视角交互假设。

## 3. Agent 体现在哪里？

它把感知结果编译成行动计划，依据状态决定继续、询问、重拍或拒绝，并在用户授权后执行、验证和补偿；不是一次文本识别调用。

## 4. 为什么不是普通 OCR＋日历？

普通串联缺少证据、矛盾检查、重复/冲突预检和事务补偿。评测中的直接执行基线用于量化这种风险。

## 5. 系统识别错了怎么办？

低置信度或矛盾会被阻断；用户确认前可取消。写入后按 event_id 回读，不一致就回滚，成功事务还能精准撤销。

## 6. 为什么不直接自动创建？

日历写入是有现实后果的操作。当前设计要求结构化确认，冲突还需要额外明确接受。

## 7. 如何避免重复日程？

草案层比较规范化标题和开始时间，日历预检再比较元数据、标题和时间容差，任一发现重复都不创建。

## 8. 日历写入失败怎么办？

日程包部分创建会触发补偿回滚；超时使用相同幂等键重试；回滚不完整会保留 event_id 并明确标记失败。

## 9. 如何保护隐私？

明确触发、短时采集、默认删临时视频、不保存音频、只留证据帧、最小日历权限。当前未实现人脸和二维码自动脱敏，因此不处理含此类信息的素材。

## 10. 为什么不做自动报名？

报名涉及身份、表单和更高外部风险，超出当前可信闭环，也会削弱初赛验证焦点。

## 11. 是否部署到真实眼镜？

没有。当前是 Windows 本地第一视角眼镜交互模拟器。

## 12. 数据集真实吗？

素材真实经过程序运行，但内容主要是固定种子人工构造，不是大规模真实校园数据；当前没有团队实拍样本。

## 13. 错误执行率低是否因为全部拒绝？

不是。我们同时报告有效覆盖率和误拒率；全部拒绝的覆盖率会是 0%、误拒率 100%，错误执行率因分母为零显示 N/A。

## 14. Google Calendar 是否真实验证？

没有完成真实端到端调用。适配器通过假服务契约测试，真实凭据和专用测试日历尚未提供。

## 15. 三人团队如何完成？

建议按可信管线、交互与素材、评测与展示三条职责并行，但共享同一数据清单、接口契约和回归门禁；当前仓库不包含多 Agent 运行功能。
