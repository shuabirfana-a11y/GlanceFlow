# 评委问答

## 1. 这和手机拍照识别有什么区别？

核心区别不在相机形态，而在行动安全闭环：字段证据、安全状态、Action Preflight｜行动预检、明确确认、回读、回滚和撤销。当前眼镜形态只是本地模拟。

## 2. 为什么必须用眼镜？

眼镜适合用户经过公告栏时低摩擦捕获，但技术闭环不依赖某款设备。我们尚未证明“必须用眼镜”，只验证了第一视角交互假设。

## 3. Agent 体现在哪里？

它把感知结果编译成行动计划，依据状态决定继续、询问、重拍或拒绝，并在用户授权后执行、验证和补偿；不是一次文本识别调用。

## 4. 为什么不是普通 OCR＋日历？

普通串联缺少证据、矛盾检查、Action Preflight｜行动预检和事务补偿。评测中的直接执行基线用于量化这种风险。

## 5. 系统识别错了怎么办？

低置信度或矛盾会被阻断；用户确认前可取消。写入后按 event_id 回读，不一致就回滚，成功事务还能精准撤销。

## 6. 为什么不直接自动创建？

日历写入是有现实后果的操作。当前设计要求结构化确认，冲突还需要额外明确接受。

## 7. 如何避免重复日程？

草案层比较规范化标题和开始时间，Action Preflight｜行动预检再比较元数据、标题和时间容差，任一发现重复都不创建。

## 8. 日历写入失败怎么办？

日程包部分创建会触发补偿回滚；超时使用相同幂等键重试；回滚不完整会保留 event_id 并明确标记失败。

## 9. 如何保护隐私？

明确触发、短时采集、默认删临时视频、不保存音频、只留证据帧、最小日历权限。当前未实现人脸和二维码自动脱敏，因此不处理含此类信息的素材。

## 10. 为什么不做自动报名？

报名涉及身份、表单和更高外部风险，超出当前可信闭环，也会削弱初赛验证焦点。

## 11. 是否部署到真实眼镜？

没有。当前是 Windows 本地第一视角眼镜交互模拟器。

## 12. 数据集真实吗？

素材真实经过程序运行，但内容主要是固定种子人工构造，不是大规模真实校园数据；当前没有团队实拍样本。

## 13. 错误执行率低是否因为全部拒绝？

不是。我们同时报告有效覆盖率和误拒率；全部拒绝的覆盖率会是 0%、误拒率 100%，错误执行率因分母为零显示 N/A。

## 14. Google Calendar 是否真实验证？

没有完成真实端到端调用。适配器通过假服务契约测试，真实凭据和专用测试日历尚未提供。

## 15. 三人团队如何完成？

建议按可信管线、交互与素材、评测与展示三条职责并行，但共享同一数据清单、接口契约和回归门禁；当前仓库不包含多 Agent 运行功能。

## Stage 7｜Agent 价值问答

### 1. 为什么不是 OCR＋Calendar API？

OCR 只能提供候选文本。Direct Execution 在本地 20 个场景中产生了可追溯的错误或未验证日历状态；它无法独立处理日期矛盾、重复、冲突确认和未知写入结果。

### 2. 为什么固定流水线不够？

固定流水线已有必要的确定性保护，但缺少跨轮最小澄清、基于观察的动作选择、确认快照失效和超时幂等回读。按 Stage 6 的“安全解析”定义，它解析 13/20 个场景，Agent 解析 17/20；按 Stage 7 更严格的实际目标完成定义，分别为 6/20 和 10/20。

### 3. Agent 具体在哪一步做决策？

每轮在观察后评估风险，枚举当前状态允许动作，再选择澄清、重采、等待、阻断、执行、验证或恢复中的一个动作；每轮最多调用一个白名单工具。

### 4. Agent 是否只是状态机换名字？

状态机约束合法转换；风险策略、澄清策略、工具契约、确认快照和恢复策略共同决定同一状态下哪些动作可选。20 个场景产生了不同动作与轨迹，不是一条固定顺序的改名。

### 5. 为什么不直接让大模型调用工具？

候选抽取不能替代确定性权限边界。外部副作用仍必须通过白名单、Safety Gate、Action Preflight、结构化确认和事务验证；当前 Agent 默认不依赖外部 LLM API。

### 6. Agent 会不会因为保守而什么都不做？

会有保护性延迟：当前 20 个场景中 4 个以重采、等待或重新确认为代价不立即写入；同时最小澄清使缺失地点和时间场景能够继续，避免固定流水线一律停住。

### 7. 17/20 目标完成是否意味着成功率只有 85%？

不是用户成功率。17/20 是 Stage 6 本地专项场景的安全解析次数，包含安全阻断；Stage 7 将“实际完成日程/撤销/取消目标”单独计算为 10/20。两者都不能外推到真实用户或真实设备。

### 8. 4/5 恢复意味着什么？

表示 5 个预设故障注入场景中有 4 个恢复到安全的预期结果，只用于验证恢复路径，不代表大规模可靠性。

### 9. 回滚失败时系统怎么办？

保留失败回滚对应的残余 event_id，进入阻断状态，公开披露未完成恢复，不重复创建，也不标记成功。

### 10. 决策轨迹是否属于思维链？

不是。轨迹只保存当前状态、风险等级、结构化规则、公开理由、工具摘要和验证结果；不记录自由推理、完整 OCR、本地路径或凭据。
