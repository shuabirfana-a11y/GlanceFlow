# Stage 6：风险感知 Agent 编排层

## 定位

Stage 6 在 Stage 1–5 既有能力之上增加确定性 Agent 编排，不替换 OCR、字段抽取、Safety Gate、Action Preflight｜行动预检或可信日历事务。Agent 默认离线运行，不依赖 LLM 或网络 API，也不具备自由调用系统能力的入口。

正式闭环为：结构化观察 → Agent 风险评估 → 枚举允许动作 → 选择一个动作 → 校验工具契约与前置条件 → 最多执行一个工具 → 验证结构化结果 → 更新状态。

## 模块边界

- `models.py`：目标、观察、动作、决策、工具结果、风险和确认快照。
- `state.py`：集中状态转换、终态约束和确认快照哈希。
- `tools.py` / `registry.py`：10 项白名单工具的输入输出、状态、副作用、超时、重试和恢复契约。
- `adapters.py`：对 Stage 1–4 现有组件的薄适配；没有复制安全门或事务逻辑。
- `risk.py`：显式风险因子及 LOW/MEDIUM/HIGH/CRITICAL 确定性覆盖规则。
- `clarification.py`：一次一个问题、同字段最多两轮，证据不足优先重采。
- `recovery.py`：只读有限重试、写入超时幂等回读、部分成功与回读不一致的回滚策略。
- `policy.py` / `orchestrator.py`：可测试的动作策略与单工具回合执行器。
- `trace.py`：只记录可展示依据，不保存自由思维链、凭据、原始音频或完整视频。
- `evaluation.py`：20 个本地确定性场景、故障注入、指标与同输入对比。

## 不可绕过的外部写入条件

`create_calendar_transaction` 只能在 `EXECUTING` 状态调用，且必须同时满足：

1. 现有 Safety Gate 返回 `READY_TO_CONFIRM`；
2. Action Preflight｜行动预检已经形成事务标识并完成重复/冲突检查；
3. 确认快照未过期，且标题、时间、地点、截止时间、通知包标识、风险与冲突状态哈希仍一致；
4. 用户处于静止状态；
5. 工具在白名单中且输入输出通过 Pydantic 校验；
6. 执行后进入独立回读验证回合。

冲突场景只接受明确的“仍然创建”。标题、时间、地点、截止时间、通知包标识、风险上升、新冲突、重新采集或超时都会使旧确认失效。

## 恢复语义

- OCR 等只读工具可在工具契约上限内重试。
- 外部写入超时后先按 `transaction_id` 回读，不重复创建。
- 部分成功或回读不一致进入 `RECOVERING`，执行补偿回滚并验证删除。
- 回滚不完整保留剩余事件标识并进入 `BLOCKED`，不会标记成功。
- 会话快照恢复时清除旧确认；若中断发生在执行或验证阶段，恢复到 `RECOVERING`，不会自动继续外部写入。

## 评测边界

`outputs/agent/` 的结果来自 Windows 本地确定性模拟器和故障注入端口。20 个场景不是用户实验，不是真实校园数据，不代表实体眼镜部署，也没有调用真实 Google Calendar。小样本结果始终保留成功次数与总次数。

对比实验让 Existing Pipeline 和 Optimized Agent 使用同一场景配置与故障端口。旧流程保留当前安全门、确认、事务自动回滚和撤销语义；没有为了展示 Agent 效果而移除既有保护。

## 当前限制

- 网页主流程仍保持 Stage 4 的稳定交互服务；新增折叠区是对当前会话的只读 Agent 调试投影。完整 Agent 闭环由模块 API、测试和专项评测驱动。
- 会话恢复使用可序列化快照，尚未引入数据库或跨设备同步。
- 当前评测规模仅 20 个本地合成/故障注入场景，不能外推为真实用户或真实设备统计结论。
