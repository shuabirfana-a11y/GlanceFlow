# GlanceFlow 团队内用户体验测试协议

状态：**待执行，尚未招募参与者**。计划在获得知情同意后招募 5–8 人；当前文件不代表已经开展测试。

## 目的与边界

评估参与者是否理解 HUD、拒绝原因、确认与撤销流程。使用固定人工素材、Windows 本地模拟器和隔离内存日历，不采集真实日历、姓名、学号、电话、二维码或音频。

## 流程

1. 介绍模拟器边界并取得书面/可追溯同意。
2. 依次完成普通活动创建、活动加截止提醒、模糊画面重拍、时间矛盾阻断、日程冲突处理、撤销刚才安排。
3. 观察员只在参与者明确求助时提示，并记录完成时间、确认次数、重拍次数、误操作与 HUD 理解情况。
4. 参与者填写 1–5 分问卷；可随时退出，退出不产生任何后果。
5. 删除会话临时素材，仅保存匿名编号的表格记录。

## 成功判定

逐任务记录是否完成，不把“系统正确拒绝危险输入”记为任务失败。样本不足时只报告描述性结果，不计算置信区间或推断总体结论。
